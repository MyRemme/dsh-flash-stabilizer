# DSH Flash Stabilizer 0.1.11 - 降低清单误停止并修复更新撤销与界面竞争

本版修复审查中可复现的三个问题。默认仍为观察模式，防护停止仍受宿主兼容性验证约束。

## 修复及原因

- **变化名称清单不再按已确认循环处理。** 旧版保护了数字编号，但持续更换模块名、文件名或中文名称的清单，仍可能因固定结论占比高而触发防护停止。现在单独检查重复短句之外的内容：至少三个不同单元、占全部单元至少 15%、不同值占这些单元至少一半时，仅通知“对象或内容仍在变化”。这些证据持续参与后续检查；清单之后若转为真正的重复循环，仍可确认并停止。该规则是保守的文本特征判断，不证明任务确实有进展，也不保证识别所有清单。
- **关闭自动更新可撤销未提交的自动安装。** 等待、下载、校验及安装前保存状态阶段均支持撤销；下载使用独立取消信号，异步边界再次检查，迟到响应及快速关闭再开启不会使旧任务继续安装。任务区分手动与自动来源，因此手动安装保留，已提交给 DSH 的安装继续完成。
- **更新面板拒绝过期状态和错误。** 用户操作使旧轮询结果失效，操作完成后重新同步；如果旧请求仍占用轮询槽位，它结束后会立即补一次同步，避免开关回跳和错误提示覆盖成功结果。
- 使用新的 `runtime-0.1.11.js` 入口，便于宿主加载新版本而不复用旧入口。

`npm run check` 通过：类型检查、构建、11 个测试文件、218 项测试。

最终安装包通过 35 个可用隔离 DSH 版本，2 个缺包未计通过，失败 0。新增命名清单场景在这些版本上均完整输出、没有停止或追加纠正。验证记录见 `evaluations/2026-11-13-review-fixes/REPORT.zh-CN.md`。

回归测试覆盖不同分块大小下的字母名称、文件名、中文名称，清单转为真实循环，自动下载取消与迟到响应，关闭后再次开启，手动安装、已提交安装，以及更新面板旧响应和旧错误。真实 DSH 核心探针新增完整输出命名清单且不停止的场景。

验证使用合成输入和确定性宿主适配器，不调用真实模型。它验证本次问题与既有防护行为，不代表线上误报率或模型恢复成功率。构建安装包不等于发布 Release 或升级用户日常运行的 DSH。
