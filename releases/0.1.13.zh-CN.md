# DSH Flash Stabilizer 0.1.13 - 完成 0.1.11 审查问题修复

保留 0.1.12 的默认全部模型监控、按渠道勾选模型、范围保存和总开关。

## 逐项修复与原因

| 审查编号 | 修复 | 为什么这样改 |
| --- | --- | --- |
| P1-1 | 围栏确认前缓存候选行，非法候选恢复为普通文本；边界先送检待处理文本，同一内容块的围栏外检测历史持续保留 | 防止丢掉围栏前的文本，避免分块方式或短代码围栏让循环检测重新起算 |
| P1-2 | 路径、扩展名和版本号不再被内部的 `/`、`.` 拆散；高度多样的清单标题采用额外的不确定性保护 | 避免固定结论很多时，把仍在逐项推进的路径、编号和名称清单自动停止 |
| P2-1 | 手动排队任务固定其目标版本；开启、关闭自动更新和后续检查不替换或清空它；保留取消过程中的手动重试 | 自动偏好不应撤销用户明确提交的安装任务 |
| P2-2 | 下载后两次空闲检查的等待状态均落盘；恢复时复用本次运行缓存并重新校验摘要、大小和归档 | 内存与磁盘保持一致，避免同一任务因聊天变忙反复下载，也不盲信缓存 |
| P2-3 | 保留 0.1.12 的旧轮询完成后立即补发同步，并补全全局、对话列表、单会话成功/失败乱序测试 | 开关操作后无需等待下一次定时轮询；旧结果和旧错误不能覆盖新状态 |
| P2-4 | 请求提前结束后保留已确认重复或已撤销纠正的显示；弹窗区分请求停止和宿主确认停止 | 已经获得的结论不能被笼统的“检测不完整”覆盖，也不能把请求当作停止成功 |
| P3-1 | 只有已确认、符合当前干预模式及请求归属的输出标记为等待干预；疑似和 guard 正文重复只记录观察 | 诊断动作应准确反映实际处理路径 |
| P3-2 | 指纹容量超限时跳过比较并断开重复计数；意外错误继续记录到具体会话、轮次和步骤 | 大型合法工具结果不等于插件异常；未能比较的结果也不能衔接成虚假的重复链 |
| P3-3 | 待绑定的帧标识仅消费一次，开始新步骤及空闲时清理，按当前请求归属接收帧 | 前一次请求的标识不能被新请求复用；旧流结束也不能清理新请求的标识 |
| P3-4 | 核对并保留诊断脚本中的 `guard`，文档明确 `language` 只控制后端日志和纠正消息，界面仍为中文 | 离线诊断与用户实际能看到的功能保持一致 |

围栏候选行缓存上限为 65,536 字符，超限显示“检测不完整 · 围栏候选行超限”，模型输出继续原样传递。短句清单保护依然属于启发式判断；带大量变化内容的真实循环可能只得到不确定通知。代码围栏中的内容不参与进展判断。

本次使用确定性模拟提供方和隔离宿主验证，不代表所有真实模型的线上准确率或取消计费效果。完整测试与安装包结果见[审查验证报告](../evaluations/2026-11-14-review-completion/REPORT.zh-CN.md)。

验证结果：类型检查、构建、14 个测试文件和 276 项测试通过；打包后 35 个隔离 DSH 宿主版本通过、2 个缺少可用包、0 失败。归档的 56 个项目文件与构建产物逐字节一致，并通过更新器安装前校验。
