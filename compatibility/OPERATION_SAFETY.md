# 操作防护独立验证

操作防护使用 `tools/pre-execute` 发起绑定调用身份的 DSH 单次审批，再通过 `tools.guard()` 在分发前执行不可被其他 guard 放行覆盖的拒绝检查。已获批准的调用在最终 guard 中重新检查权限、参数和配置版本；批准不缓存为前缀权限。

## 已验证宿主

| DSH | 验证方式 |
| --- | --- |
| 0.2.1-rc.2 | 隔离加载实际发布的 Cordis、AgentLoop、Tools、Approval 等宿主核心 |
| 0.2.2-rc.1 | 隔离加载实际发布的宿主核心与 Native 工具执行器 |

宿主版本从实际安装元数据识别。用户提供的 `hostVersion` 监控提示不能解锁操作防护支持。旧版防空转兼容矩阵不参与安全功能解锁。

## 验证内容

- 已识别的提权、只读写入和删除在工具体之前被阻止。
- 下游拒绝保持有效，其他前置 hook 强制放行也无法绕过最终硬拒绝或单次审批要求。
- 拒绝、取消、缺少服务、异常审批结果都不会进入工具体。
- 只有当前调用收到 `allowed-once` 后才允许一次模拟工具体执行；下一次调用重新审批。
- 宿主日志实际生成成对的 `approval/asked` 与 `approval/decided`。
- 暂停全局或单对话监控、排除当前模型，不影响操作防护。
- 配置持久化、写入失败保留原设置、损坏配置阻止受保护调用、卸载清理。
- 诊断导出不包含命令正文、工具参数、工作区路径或原始会话 ID。

```powershell
npm run check
npm run test:safety-host
node scripts/safety-host-probe.mjs . 0.2.2-rc.1
node scripts/safety-host-probe.mjs .compat-cache/runtimes/0.2.1-rc.2 0.2.1-rc.2
```

测试使用确定性模型与无副作用的模拟工具体，不启动 shell、不调用 UAC、不删除目标文件。权限解析器按真实服务接口提供测试值，因此这些测试证明宿主执行管线及审批行为，不代表已验证 Windows 沙盒本身，也不代表完成桌面 UAC 交互测试。

未缓存旧版宿主时，单元测试会跳过该版本的实际宿主用例；可通过项目现有版本测试脚本准备隔离运行时后再次验证。操作防护为自愿启用功能，默认关闭；开启前可在面板查看实际版本和可用状态。
