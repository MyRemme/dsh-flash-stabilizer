# 修复后复审与回归验证

日期：2026-11-11。环境：Windows、Node.js 24.20.0、npm 11.19.0。

本轮已修复审查发现的问题，复审未发现阻止提交的缺陷。以下结果证明检测和宿主恢复流程通过回归检查；真实模型在线恢复效果仍未验证，发布包不开放 auto。

## 修复与复审

- `assist` 只保存纠正意图，等待持久化 `turn/end` 与 idle 后通过 `followup()` 开启独立回合。原回合 `max-tokens` 不再影响恢复回合读取工具结果；不再往 `nextStep` 注入纠正消息。
- 每个用户任务最多两个纠正回合；发送前重新检查待执行对象、用户队列、停止信号、会话开关及卸载状态。错误或没有结束原因时丢弃待执行纠正，避免异步回调恢复已取消的任务。
- 围栏解析记录标记和开启长度，要求关闭行长度足够且只含尾随空白。逐字符处理跨 delta、CRLF、缩进和非法 info string，状态大小不随代码行长度增长；提供方 chunk 保持原样。
- 周期覆盖率计入首部不完整周期，使短句的最小合法谐波保持稳定；连续确认同时要求低新内容比例。没有采用建议中的 `gcd >= 2` 放宽规则，避免两个不同周期仅因共有因数而被视为稳定循环。
- 会话命中更新 LRU，运行时禁用在实例替换和淘汰后保留；同 ID 替换先移除旧状态再检查容量。无结束原因的 idle 清理待执行恢复，live frame start 同步请求标识。
- Bundle 默认模型列表补齐 `deepseek-v4.1-flash`，与配置默认值保持一致。

## 回归结果

| 检查 | 结果 |
|---|---|
| `npm run check` | 类型检查、构建和 112 项测试通过，6 个测试文件 |
| 安装包的官方宿主矩阵 | 35 通过、2 unavailable、0 失败 |
| 真实历史空转原始流离线回放 | 20/20 检测确认，保留原始分块边界，新增模型请求为 0 |
| 真实宿主取消历史流 | 0.2.2-rc.1 测试副本消费 5,319/128,004 个分块后中断，迭代器关闭，提交一次确定性续接 |

增强的宿主矩阵包含：原回合耗尽输出、独立纠正回合调用工具、工具仅执行一次、下一请求收到对应调用 ID 和准确结果正文、用户停止后无追加请求、无注入残留，以及原有流无损、预算、会话禁用和卸载检查。

核对官方类型后，测试同时识别旧版 `user` 消息内的 `tool-result` 块和新版独立 `tool` 消息。两种结构都校验来源、调用 ID、非错误状态及结果正文，不以请求次数代替结果交付验证。

历史样本确认点为第 3,590–34,093 个 reasoning 字符，按原日志时间轴为约 7.5–54.9 秒。这些是已筛选失败样本的离线结果，不能据此推导总体误报率、真实节省费用或恢复成功率。
