# 0.1.2 优化与复审

日期：2026-11-11。基线：0.1.1，提交 `a3d500b2b2ed0ade6bc9adb672ae1c2e98425c94`。环境：Windows，Node.js 24.20.0。

## 改动

- 每个模型请求确认一次重复后，立即释放检测窗口并停止扫描当前 delta 的剩余文本和后续 chunks。宿主仍原样接收全部 chunks，观察模式不会停止模型。
- 周期匹配只扫描一次 Unicode 字母，推导满足两个不同字母要求的最小后缀长度，避免为每个周期建立正则匹配数组和 Set；字符匹配改用相邻周期比较，完整覆盖后提前退出。保持原来的周期范围、最短周期优先、覆盖率、确认阈值和代码围栏豁免。
- 流包装器持有自己的请求实例。旧流的后续输出不会进入新流的检测器，旧流结束也不会删除新流请求。延迟消费的旧迭代器不会覆盖新步骤的状态。
- 包验证脚本默认从 `package.json` 读取版本，避免升级后误测旧包。

## 本地检测基准

脚本：`scripts/benchmark-detection.mjs`，对照保存在忽略目录的旧版构建。每项预热后交替测量 5 轮，报告每轮平均耗时的中位数。后缀项目每轮 500 次，长流项目每轮 2 次。两种长流输入均为 262,144 个字符，使用默认设置。

| 工作负载 | 0.1.1 毫秒/次 | 0.1.2 毫秒/次 |
|---|---:|---:|
| 4096 字符完整周期后缀 | 7.9649 | 0.0361 |
| 4096 字符变化文本后缀 | 1.5194 | 0.0143 |
| 长重复流，单 delta | 8188.3538 | 0.3576 |
| 长重复流，73 字符分片 | 7242.4366 | 0.4287 |

长流收益主要来自确认后不再扫描剩余文本。这是同机合成输入的检测器 CPU 耗时，随环境和输入变化；不代表模型生成加速、Token 节省或恢复质量提升。本次没有发送任何真实模型请求。

复查方式：构建旧版并保留其 `dist` 目录，在当前版本执行 `npm run build`，再运行 `node scripts/benchmark-detection.mjs '<旧版 dist 目录>'`。不需要 API Key 或历史会话内容。
