# 0.1.8 仓库入口与自动更新验证

插件面板增加固定 GitHub 仓库链接和更新区域，使用 DSH 原生按钮、开关、主题与认证连接。仓库仍为私有，正式 Release 是自动更新来源，不安装任意分支提交。

## 验证

- 191 项测试通过，覆盖只接受递增正式版本、固定资产名、SHA-256 校验、安装包身份、路径/链接拒绝、安装脚本拒绝、兼容性拒绝、六小时调度、检查失败撤销旧候选、标准安装的宿主元数据识别、用户输入优先与既有防空转回归。
- 更新调度在所有 Agent 空闲且没有待处理输入时安装，下载后再次检查；回归确认忙碌时等待、不调用安装器。
- GitHub 资产重定向限制到官方资源域名，不转发令牌；无效目标被拒绝。上游错误、凭据及本机路径不返回界面。
- 自动更新开关与需重启状态保存在本机 profile；刷新和重载保留设置。未开启自动更新时不会自动请求 GitHub。
- 真实 DSH 0.2.1-rc.2 隔离插件管理器完成两种安装验证：HMR 宿主返回 `applied`，新模块实际运行；无 HMR 返回 `restart-required`，旧模块保留至重启。使用合成插件及本地 tarball，无模型请求。
- 35 个可用发布宿主通过交付包防空转回归，2 个发布版缺少宿主包，未计运行通过。此矩阵不代表全部版本均支持更新服务。
- 16 个桌面/手机及明暗主题视图完成布局与交互检查，验证仓库目标、更新开关和检查按钮。
- 自动化浏览器在页面加载前阻断音频与下载资源，禁用扩展、下载与 Service Worker，并保持无头运行；合成请求验证提示音和压缩包均被本地拦截，不唤起外部下载器。

实际标准安装校验发现，pnpm 迁移后的插件目录无法直接解析宿主 peer 元数据，0.1.7 因此可能降级 observe。0.1.8 使用启动器提供的 `installAnchor` 读取真实宿主包版本；不靠配置提示跳过验证。版本已发布后不覆盖原 Release，修复以新补丁版发布。

## 更新与鉴权边界

私有发布需要有仓库读取权限的 GitHub 凭据。支持指定环境变量或已有 Git 凭据助手，凭据仅在主机进程内使用，不写状态、不发送诊断或会话。只有正式 Release 的安装资产会被下载。SHA-256 校验是完整性验证，不是独立发布签名。

检查与下载有时间/大小边界；安装使用 DSH 自身包管理生命周期，不删除当前插件来尝试恢复，不授权新构建脚本，不停止进程，不自动重启。宿主报告失败或需重启时界面明确显示，不能把下载完成当作新版已运行。

新增固定依赖 `tar` 与 `semver` 随包交付；依赖审计未报告这两个新模块的问题。现有 DSH 测试宿主的 `zod` 依赖链仍有已知 npm 审计告警，本次未替换宿主依赖，也不据此声称所有依赖无漏洞。
