# 0.1.12 模型监控范围验证

日期：2026-11-14（Asia/Shanghai）。在本地 0.1.11 修复基础上加入模型范围功能，保留变化清单不确定性保护、自动更新任务撤销及更新轮询修复。本次生成本地安装包，未发布 GitHub Release，也未替换日常 DSH 安装。

## 问题与修改原因

旧版默认使用 Flash 模型别名白名单，第三方渠道的完整模型名可能与白名单不同，因此会被归类为不在监控范围。0.1.12 默认 `modelScope: all`，不再通过模型名称猜测是否应监控；辅助请求、关闭监控的会话及无法绑定当前步骤的请求仍遵守既有边界。

选择性监控按渠道与完整模型标识精确匹配。这样既能识别第三方自定义名称，也能区分两个渠道提供的同名模型。界面保留「启用监控」总开关，新增「全部模型／仅选中的模型」、搜索、复选列表、刷新列表和保存按钮。全部模式保留已有勾选，选中模式的空列表表示不监控任何模型。

设置保存在当前 profile 的 `.flash-stabilizer/model-scope.json`，保存成功才替换当前生效范围，并在下次加载插件时、第一条请求之前恢复。保存失败保留原范围；没有 profile 目录的宿主明确提示仅本次运行有效。缩小范围立即停止跟踪被排除的流、撤销待执行纠正，但不取消用户的模型输出；扩大范围从下一次请求生效。

模型目录来自宿主接口及本次运行观察到的路由。读取目录不生成聊天请求，单个渠道失败不影响其他渠道。真实渠道和模型标识仅通过 owner 设置接口访问并保存在本机，状态与诊断导出只提供范围和选择数量。

附件审查中的旧监控轮询阻塞即时同步问题与本次功能相关，一并修复；离线诊断补充 `guard` 和模型范围信息，文档说明语言选项的实际作用范围。此报告不表示附件中其余检测器、更新器及事件状态问题均已修复。

## 验证结果

- `npm run check` 通过：类型检查、两次构建、12 个测试文件、234 项测试全部通过。
- 界面最后补充长模型名换行及窄容器布局，随后单独复核客户端 35 项测试全部通过。
- 范围测试覆盖旧、新两种流适配器：第三方自定义名称及非 Flash 名称默认监控；同名不同渠道精确隔离；空选中列表；切回全部保留选择；流进行中撤销待执行纠正；保存前建立但尚未消费的旧迭代器不能越过新范围。
- 保存测试覆盖校验、去重、失败保持原设置、重载前持久化恢复，以及第一条请求就按保存范围筛选。
- 界面交互测试覆盖切换、勾选、保存、失败后保留草稿，以及旧轮询成功或失败均不能覆盖已保存状态，旧请求完成后立即重新同步。
- 接口测试覆盖 owner 权限与真实路由不进入诊断导出。
- `node scripts/test-package.mjs artifacts/dsh-flash-stabilizer-0.1.12.tgz artifacts/host-results-0.1.12.json`：35 个隔离宿主版本通过，2 个不可用，0 失败。每个通过的版本均执行第三方模型默认监控、按渠道隔离、只监控选中模型、恢复全部监控四项新增场景，并保留原有停止、纠正、工具、输出透传和卸载探针。
- 不可用的 `0.1.2-alpha.1`、`0.1.3-alpha.1` 缺少对应 npm 宿主发布包，未计为通过。
- 安装包 56 个项目文件与当前构建产物逐字节一致，通过更新器的归档校验；`git diff --check` 无格式错误。

宿主测试使用真实已发布 Cordis / AgentLoop 核心和确定性模型适配器，不调用真实提供方、不发送私人会话。客户端测试使用 React 与 JSDOM，未执行日常 DSH 桌面安装或视觉验收。扩大监控范围不等于完成每种模型的线上准确率、误报率或恢复效果验证。
